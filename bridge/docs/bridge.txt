你这个问题其实问到了核心：**Lehman 的“两棵树”在 3×4 Bridg-It 里怎么直接看出来？**

如果你只想要 **3×4 Bridg-It 的答案**，不用完整算法。

先说明一下：Bridg-It 是 Shannon switching game 的一个特殊网格版本。Lehman 定理告诉我们：Maker 必胜等价于存在两棵边不相交的连接树。([Hexwiki][1])

---

## 3×4 Bridg-It（红方连接上下）的解

假设红方目标：

```
Top

● ● ●
 ● ● ●
● ● ●
 ● ● ●

Bottom
```

（实际 Bridg-It 是两套交错颜色的点）

红方第一步：

> **占据中央竖直桥**

也就是中间列的第一条向下连接。

示意：

```
    |
 ●--●--●
    |
 ●--●--●
    |
 ●--●--●
    |
 ●--●--●
```

为什么？

因为它建立了一个“双通道”。

## 两棵树怎么画？

假设目标是：

```
A = 上边
B = 下边
```

把上下边压缩成两个节点：

```
        A
      / | \
     /  |  \
    o---o---o
    |   |   |
    o---o---o
    |   |   |
    o---o---o
      \ | /
        B
```

现在找：

### Tree 1（左路）

```
A
|
1
|
4
|
7
|
B
```

例如：

```
A
|
●
|
●
|
●
|
B
```

---

### Tree 2（右路）

完全避开 Tree 1 的边：

```
A
|
3
|
6
|
9
|
B
```

即：

```
A
|
●
|
●
|
●
|
B
```

两棵树：

```
Tree 1:

A
|
左
|
左
|
B



Tree 2:

A
|
右
|
右
|
B
```

没有共享边：

```
Tree1 ∩ Tree2 = ∅
```

所以 Maker 必胜。

## 人脑找两棵树的方法

对于小棋盘，不需要 Lehman 算法。

用这个技巧：

### 第一步：

先找一条最短连接：

```
A
|
|
|
B
```

### 第二步：

问：

> 如果这条路全部被剪掉，还有另一条吗？

例如：

```
A
 |       |
 |       |
 |       |
 B       B
```

如果答案 yes：

两棵树存在。

---

## 为什么 3×4 很容易？

因为它有宽度冗余：

```
左边路径

中间路径

右边路径
```

Breaker 一次只能破坏一个桥。

所以：

```
路径1 被切

↓

路径2 继续
```

这就是 Lehman 思想。

---

## 一个重要区别

你之前问“算法怎么找到两棵树”。

对于真正程序：

不是这样：

```
找左路
找右路
```

而是：

```
最大流 / matroid partition
        ↓
找两棵 edge-disjoint spanning trees
```

但对于 3×4 Bridg-It：

肉眼直接画两条互不共享的上下路径即可。
