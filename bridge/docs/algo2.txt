是的，**Alfred Lehman 的 Shannon switching game 解法是公开的**，而且是这个领域的经典结果。论文：

A Solution of the Shannon Switching Game

发表于 1964 年，标题就是 **A Solution of the Shannon Switching Game**，页码 687–725。([工业与应用数学学会][1])

不过要注意：

**Lehman 并没有给出一个像 Dijkstra 那样“逐步搜索路径”的算法。**

他的核心贡献是：

> 把 Shannon game 转化成 **Matroid（拟阵）理论问题**，给出了 Maker 必胜的充要条件。

后来证明，这个判定可以通过多项式算法实现，例如 matroid partition 或网络流方法。([维基百科][2])

# 1. 先定义游戏

图：

[
G=(V,E)
]

两个特殊节点：

[
s,t
]

两个玩家：

## Short（Maker）

选择边：

```
e1,e2,e3...
```

目标：

最终自己的边连接：

```
s -------- t
```

---

## Cut（Breaker）

删除边。

目标：

让：

```
s  ✕  t
```

永远无法连通。

---

# 2. Lehman 的核心定理

这是最重要的：

> Short 有必胜策略
> **当且仅当图中存在两棵边不相交的 spanning tree（生成树）。**

也就是：

存在：

Tree A:

```
        s
       / \
      a   b
     /     \
    c       t
```

Tree B:

```
        s
       / \
      x   y
     /     \
    z       t
```

要求：

[
E(Tree_A)\cap E(Tree_B)=\emptyset
]

即：

两棵完全独立的连接结构。

([BPB][3])

---

# 3. 为什么是“两棵树”？

这是整个算法思想。

假设只有一条路：

```
s--a--b--t
```

Breaker：

删：

```
a--b
```

失败。

但是如果：

```
Tree A:

s--a--b--t


Tree B:

s--x--y--t
```

Breaker 删除 Tree A 的边：

```
s--a  X
```

Maker 走 Tree B。

---

更正式：

Breaker 每破坏一棵树中的边：

```
Tree A 被切成两个部分
```

那么：

Tree B 中一定存在一条跨越这两个部分的边。

Maker 选它。

所以：

Breaker 不可能同时破坏两套独立连接结构。

---

# 4. Lehman 算法实际上怎么做？

如果你给一个图：

例如：

```
      a
     / \
s---b---c---t
     \ /
      d
```

目标：

判断：

有没有两棵 edge-disjoint spanning trees。

算法步骤：

---

## Step 1

建立两个拟阵：

### Matroid 1

图的 graphic matroid：

独立集合：

> 不包含环的边集合

也就是森林。

例如：

合法：

```
a---b---c
```

非法：

```
a---b
 \  |
  \ |
   c
```

形成环。

---

### Matroid 2

复制一个。

问题变成：

能否把边集合分成：

```
Tree1

+
Tree2
```

---

## Step 2

检查：

是否存在：

[
E=E_1\cup E_2
]

其中：

[
E_1,E_2
]

都是 spanning tree。

---

如果：

存在：

```
YES

Short wins
```

否则：

```
NO

Cut wins
```

# 5. 后来的算法实现

实际工程不会直接跑 Lehman 1964 论文。

现在通常：

## 方法1：Nash-Williams / Tutte 定理

判断：

图是否有 k 棵边不相交生成树。

对于 k=2：

条件：

对于任意顶点划分：

[
p
]

跨越划分的边数：

[
\geq 2(p-1)
]

满足：

有两棵生成树。

---

## 方法2：网络流

把问题转换：

寻找：

```
两个独立 s-t connectivity structures
```

然后最大流。

复杂度：

Polynomial time。

([维基百科][2])

# 7. 一个非常重要的区别

很多人误解：

> "Shannon game 是不是找最优路径？"

不是。

它不是：

```
找一条最好路径
```

而是：

```
判断网络有没有足够冗余
```

本质：

可靠性问题。

类似：

金融里的：

```
单因子风险：

    股票A
       |
       崩溃


多因子结构：

    股票A
    / | \
 因子1 因子2 因子3

```

Lehman 的思想：

> 不要依赖一条路径，要有两套独立结构。

先说明一个关键点：

**Lehman 原始证明不是一个“搜索必胜走法”的算法，而是一个判定算法：**

> Shannon switching game 中 Maker（Short）是否必胜 ⇔ 图中是否存在两棵边不相交的生成树（two edge-disjoint spanning trees）。

所以现代程序实现可以拆成两个部分：

1. **判定有没有两棵 edge-disjoint spanning tree**
2. 如果有，提取两棵树作为 Maker 的“战略骨架”

# 2. 思路

寻找：

```
Tree A:

      s
     / \
    a   b
     \ /
      t


Tree B:

      s
     / \
    x   y
     \ /
      t
```

要求：

```python
TreeA.edges ∩ TreeB.edges = ∅
```

也就是：

第一棵树占用一些边后：

> 剩余图仍然可以生成第二棵树。

因此：

1. 求一棵 spanning tree
2. 删除它的边
3. 再求第二棵 spanning tree

这是一个**简化版 Lehman 判定器**。

严格 Lehman 算法更强，但对于很多实际 Shannon Game 小图，这个版本足够。

# 3. Python 实现

```python
import networkx as nx


def get_spanning_tree(G):
    """
    返回一棵生成树
    """

    if not nx.is_connected(G):
        return None

    tree_edges = list(
        nx.minimum_spanning_edges(
            G,
            algorithm="kruskal"
        )
    )

    T = nx.Graph()
    T.add_edges_from(
        [(u, v) for u, v, _ in tree_edges]
    )

    return T



def find_two_disjoint_spanning_trees(G):
    """
    Lehman思想：
    寻找两棵边不相交生成树
    """

    # 第一棵树
    T1 = get_spanning_tree(G)

    if T1 is None:
        return None


    # 删除第一棵树的边
    G2 = G.copy()

    G2.remove_edges_from(
        T1.edges()
    )


    # 第二棵树
    T2 = get_spanning_tree(G2)


    if T2 is None:
        return None


    return T1, T2



def shannon_game_solver(G):

    result = find_two_disjoint_spanning_trees(G)

    if result:

        T1, T2 = result

        return {
            "winner": "Maker",
            "tree1": list(T1.edges()),
            "tree2": list(T2.edges())
        }

    else:

        return {
            "winner": "Breaker"
        }
```

# 5. 如果想生成 Maker 策略

Lehman 的证明实际上给出了一个策略：

假设：

```
T1
T2
```

两棵树。

Maker：

优先保持：

```
T1 ∪ T2
```

中的边。

Breaker 删除：

```
T1
```

中的边。

Maker 转向：

```
T2
```

---

伪代码：

```python
def maker_move(T1,T2,breaker_edges):

    remaining=[]

    for e in T1.edges():

        if e not in breaker_edges:
            remaining.append(e)


    for e in T2.edges():

        if e not in breaker_edges:
            remaining.append(e)


    return remaining[0]
```

# 6. 但是：这个代码距离论文版还有差距

上面的算法有一个问题：

假设：

```
Tree A
```

随便取了一棵。

可能：

```
Tree A

拿走了关键边
```

导致：

```
剩余图没有第二棵树
```

但实际上：

可能存在另外一种 Tree A。

所以严格算法需要：

寻找：

[
T_1,T_2
]

使：

[
T_1 \cap T_2=\emptyset
]

这就是：

* matroid intersection
* matroid partition
* Nash-Williams/Tutte theorem

# 7. 更接近 Lehman 的现代算法

实际应该这样：

```
输入 Graph G

↓

计算最大数量 edge-disjoint spanning trees

↓

如果 >=2:

Maker wins

↓

输出两棵树
```

对应：

```
Edmonds matroid partition
          |
          |
   graphic matroid
          |
          |
 two spanning trees
```

# 8. 如果做 AI / 游戏环境，我建议

不要实现论文级 Matroid。

可以做：

```
State:
    当前剩余边

Action:
    Maker选择边

Opponent:
    Breaker删除边

Reward:
    是否连接 s-t
```

然后：

* Lehman solver = Oracle
* RL agent = 学习策略

结构：

```
          Shannon Game

              |
       ----------------
       |              |
 Lehman Solver     RL Agent
 (最优答案)        (学习)
       |
  reward shaping
```

这其实非常适合做一个强化学习环境。
