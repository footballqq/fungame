## 一、踩过的坑：为什么“手拍像素坐标”一定会翻车？

在第一版原型中，我们曾尝试直接估算 SVG 像素坐标来画几何题，结果被用户一眼揪出 3 类典型“不严谨”问题：

1. **斜正方形“看着像正方形，实际不是直角”**（如 `9×5` 缺 `4×1` 勾股斜切 `41 = 4² + 5²`）：
   - **问题原因**：手写第四个顶点坐标时少减了 1 个单位格（25px），导致顶角不是 90°，且顶部拼合区域缺少纵轴竖直分割线，孩子看不出 ① 和 ② 飞到上方后各自占哪一块。
   - **根治方案**：在真实数学坐标系（y 轴向上）中，用向量加法直接计算第四顶点 `T = A + (D - M)`，并对每块平移后的三角形做真实向量平移（`①' = ① + (+4, +5)`、`②' = ② + (-5, +4)`），显式绘制纵轴拼合分界线与 `①' / ②'` 编号。
2. **4 倍旋转补大弦图“只画了外框和中间洞，没有 4 块严丝合缝包裹”**（如第 14 讲附加题 4 多边形 `ABCFDE`）：
   - **问题原因**：随手画了一个框和一个倾斜小正方形，没有按真实条件 `AB=8, BC=12, AE=CF, ED+DF=14` 解出精确的 `D` 点坐标，导致 4 块旋转后根本拼不严。
   - **根治方案**：以大正方形中心 `(0, 0)` 为旋转中心，令 `AE = CF = t`，利用 `|EF|² = p² + q²` 与 `p + q = 14` 解出直角边 `p, q` 及单位方向向量 `u, v`，精确求出 `D` 点，再通过 90° 旋转矩阵 `rotatePt(pt, 0, 0, 90 * k)` 生成全部 4 块全等多边形（①②③④ 四色区分），天然严丝合缝包裹正中央 `14×14` 空洞！
3. **长方形内斜嵌多个正方形“画到第 6 块越界了”**（如第 14 讲例题 12）：
   - **问题原因**：手动逐个算斜顶点极易算偏。
   - **根治方案**：定义单个斜正方形的正交基向量 `u = (b, -a)` 和 `v = (a, b)`，按 `(col, row)` 网格坐标批量生成全部 6 块，再按所有顶点的 `(minX, minY)` 归零平移，自动算出外接包围盒恰好为 `20 × 22`！

## 二、可复用的几何构造与验算黄金规范

未来开发任何几何课件，强制执行 **“数学坐标系推导 → 自动映射 SVG → 自动化数学验算”** 三步法（核心代码见 [geo_verify.js](file:///E:/users/kpan/BaiduSyncdisk/program/aigc/fungame/math/geo_pythago/js/geo_verify.js)）：

### 1. 永远在“数学坐标系 (y 向上)”算完，再统一映射 SVG (y 向下)
```js
function toSvg(pt, ox, oy, scale) {
  return [
    Number((ox + pt[0] * scale).toFixed(2)),
    Number((oy - pt[1] * scale).toFixed(2))
  ];
}
```
不要在 SVG 坐标系里心算旋转和向量加减，否则极易把正负号搞反。

### 2. 用“鞋带公式 + 向量点积”做自动化数学验收门禁
把以下 4 类断言写进 `verifyAllConstructions()`，并挂载到 `pytest` 自动化测试中：
- **边长断言**：`dist(P, Q) === 题目给定边长`（误差 `< 1e-5`）
- **垂直度断言**：相邻两边向量点积 `dot(u, v) === 0`（确保正方形/直角三角形是真直角）
- **鞋带公式面积断言**：`polygonArea(pts) === 题目标准答案面积`
- **拼合面积守恒断言**：
  - 剪拼题：`拼合前各块面积之和 === 拼合后各块面积之和 === 目标图形面积`
  - 弦图 4 倍旋转题：`4 × 单块面积 + 中间洞面积 === 外接大正方形面积`
