# IMO 2026 第 4 题错误与修复记录

本文记录交互教学系统在 2026-07-22 评审中发现的问题、影响和修复方案。题目与策略以项目内的 `IMO_2026_Problems_CN.pdf` 及 `IMO-2026-notes.pdf` 第 11 页为核对依据。

## 已修复

| 编号 | 问题 | 影响 | 修复 |
| --- | --- | --- | --- |
| E-01 | 旧说明称 `90° = (n/2)θ` 对所有 `θ = 180°/n` 都是整数倍。 | 当 `n` 为奇数时结论错误。例如 `θ=60°` 时，`90°=1.5θ`。AI 会错误显示为 `2θ`。 | 改用正确构造：先得到直角三角形，再取满足 `45° < kθ ≤ 90°` 的整数 `k`，构造两个分别含 `kθ` 与 `(n-k)θ` 的分支。 |
| E-02 | 演示第 5 步采用 `t=0.2857`。 | 该切线在点 P 只形成约 `9.09°`，并不能展示 `45°` 必胜角。 | 修正为 `t=5/7`，使两个子三角形在 P 处均形成 `45°`。 |
| E-03 | Python 测试复制了一份几何算法。 | 测试通过不能证明浏览器实际运行的 JavaScript 正确。 | 增加由 pytest 调用的 Node.js 回归测试，直接加载并验证前端几何、AI 策略和动画数据。 |
| E-04 | 教学文档与引导页重复传播 E-01。 | 用户会得到错误的奇数 `n` 证明。 | 已用题源中的正确构造替换，并明确 `θ=60°` 是奇数 `n` 的验证案例。 |
| E-05 | 文档文件名含 `2024`，正文和题源均为 2026。 | 文档身份不一致，容易误用或错误引用。 | 将主文档统一命名为 `imo2026Q4.md`。 |
| E-06 | 鼠标事件直接使用视口 CSS 坐标，且每次移动都重设画布尺寸。 | 在缩放、高 DPI 或边框尺寸变化时，远离中心的剪切预览会发生视觉偏移。 | 仅在尺寸变化时重设画布；将鼠标与触控坐标按实际画布显示尺寸归一化。 |
| E-07 | 圆弧绘制按两个极角的数值大小选择起止点。 | 当射线跨越 `-π/π` 边界时，显示的弧线和标签会落在补角一侧，导致分割角看起来错误。 | 根据已计算的内角大小选择圆弧方向，并按该方向计算标签的中点。 |
| E-08 | 剪切预览只标示了边界切点 P 的两部分角。 | 无法直观看到切线在对顶点处如何分割原角。 | 同时绘制对顶点的两条分割弧和 `∠A₁ / ∠A₂`（或 B、C）数值。 |
| E-09 | 单于选择层使用不透明全屏遮罩。 | 玩家选择前看不到当前切线和两个候选三角形。 | 保留切割画面，使用绿色 `T₁`、红色 `T₂` 和黄色切线，并将选项改为顶部悬浮卡片。 |
| E-10 | 演示画布在隐藏状态下可能先以零尺寸测量。 | 首次打开“题目说明与动画演示”时，步骤 1 可能没有可见图像。 | 仅在画布可测量时更新尺寸，并在切换到演示页后等待布局完成再渲染首帧。 |
| E-11 | 两个候选三角形均含 θ 时仍要求单于手动选择。 | 已形成强制胜局却没有立即显示木兰获胜；单分支含 θ 的含义也不明确。 | 双分支均含 θ 时自动判定木兰获胜；其余选择卡片明确标示“保留即木兰获胜”或“可继续防守”。 |
| E-12 | 隐藏画布重新显示后，尺寸监听器可能在手动渲染之后再次清空画布。 | 初始页面切换到演示或解密标签时，三角形会消失。 | 尺寸监听器在有效测量后触发对应画布的重绘；解密页切换时也立即绘制当前三角形。 |
| E-13 | 原启发式解密只有少量概念卡片，证明前提与操作步骤脱节。 | 用户难以将角度显示、策略与结论连接起来。 | 重构为六步可加载图形的教学流程，并以 `θ=60°` 覆盖奇数 n 的关键构造。 |
| E-14 | 细长三角形沿竖直方向显示，角弧和数字容易重叠。 | 大面积画布没有被有效利用，读数困难。 | 显示层将最长边旋转为水平并减小边距，保持距离与角度不变。 |
| E-15 | 鼠标切点只能停在近似特殊角。 | 用户可能看到 89.9° 或 90.1°，难以构造精确高线或目标角。 | 靠近 90° 或 θ 时自动求解并吸附到精确切点，显示吸附提示。 |
| E-16 | 证明使用 D，而游戏与画布使用 P，且保留三角形会丢失切割点标识。 | 图文符号不一致，用户无法确认哪一个顶点来自本次切割。 | 全部教学公式统一为切割点 P；预览、候选和保留三角形均显示 P 标签。 |
| E-17 | 动画固定使用 θ=45°。 | 用户会把 90° 平分的特例误解为一般策略，无法观察 θ=36° 的正确构造。 | 演示页与主界面的 θ 同步；有效 θ 动态生成 $kθ$ 分支，非整除 θ 明确展示无保证必胜策略。 |
| E-18 | 第 ④ 步示例的直角顶点与公式使用的顶点名称不一致。 | 画布中 BC 是直角边，文字却称 BC 为斜边。 | 统一为 $∠A=90°$、BC 为斜边、$∠B≤45°$ 的示例三角形，并加回归断言。 |
| E-19 | 鼠标只能近似定位边界切点 P。 | 用户无法稳定以小步长调整所需角度。 | 悬停激活 P 后，左右方向键以 0.1° 调整 ∠P₁，并实时重算精确切点。 |
| E-20 | 木兰获胜仅显示在状态条，历史没有结果且没有终局提示。 | 玩家可能继续操作，无法确认游戏已结束。 | 记录普通获胜与强制胜局，停止操作并弹出获胜对话框。 |
| E-21 | 角度显示为一位小数，胜负判断却使用远小于显示精度的容差。 | 画面显示 `36.0°` 时仍可能被标为安全角并继续游戏。 | 目标角与危险倍数角使用 `0.05°` 交互容差；显示为 `θ` 即触发目标角与终局判定。 |
| E-22 | 点击已选定的 P 执行切割时，鼠标位置可能在最后一刻改变切点。 | 精细调整好的角度会被无意移动。 | 悬停激活 P 后，左右键继续以 `0.1°` 调整，空格键直接按当前 P 执行切割。 |
| E-23 | 重置局面沿用含有 $k\theta$ 的简单三角形。 | 例如 $\theta=36^\circ$ 时开局就有 $72^\circ=2\theta$，玩家可直接拆出目标角，缺乏探索难度。 | 重置、模式切换和快速换角改用不含 $\theta$ 或 $k\theta$ 的高难度开局；教学形状预设仍可按需加载。 |
| E-24 | 对顶点的两个分割角标签紧贴弧线绘制。 | 在窄角或细长图形中，数值会压在一起而无法辨读。 | 标签移至弧线外，用错开半径的虚线箭头分别指向对应角弧。 |
| E-25 | 键盘调整依赖页面当前焦点，但 Canvas 默认不可聚焦。 | 鼠标刚选好 P 后，焦点仍可能停留在按钮，导致左右键无响应。 | 主画布加入键盘焦点；指针进入或按下时自动聚焦，仅在输入控件保持焦点时不劫持方向键。 |
| E-26 | 快捷键说明紧贴 P 且没有说明方向语义。 | 提示与几何标签争抢空间，玩家也会误以为左右键总是对应固定的顺、逆时针。 | 提示移至画布顶部，明确左键使 $\angle P_1$ 减少、右键使其增加、空格执行；说明屏幕旋转方向随所选边变化。 |
| E-27 | 画布按一位小数显示，历史却按整度四舍五入，判定又采用独立的浮点容差。 | 例如真实角为 $17.94^\circ$ 时，画布显示 $17.9^\circ$、历史却显示 $18^\circ$，看起来像漏判目标角。 | 统一为一位小数规范化：画布、历史、候选提示和胜负判断共用同一函数；$17.9^\circ$ 不会记录成 $18^\circ$，显示 $18.0^\circ$ 则必按目标角判定。 |
| E-28 | 快捷键提示作为 Canvas 内浮层显示。 | 提示会遮挡靠近上边界的三角形边和角标注。 | 将提示移至画布容器外的正上方，不再占用绘图区域。 |
| E-29 | 切点处仅标 `P₁/P₂`，未说明两者对应哪一侧边。 | 用户无法快速验证标签是否与自己看到的 A、B 两侧一致，容易误认为标号反了。 | 标签改为 `P₁(靠A)`、`P₂(靠B)` 等动态形式；文档明确在边 AB 上时 $P_1=\angle APC$、$P_2=\angle CPB$。 |
| E-30 | 各类角标注各自按固定半径绘制。 | 在极细三角形或切点靠近顶点时，顶点角、P 两侧角和分割角会叠在一起。 | 渲染器加入统一的标注布局表：测量文字边界，检测与已有标注、顶点、切点的碰撞，自动尝试不同方向与距离，并以箭头回指。 |

## 回归验收

- `python.exe -m pytest -q`：验证 Python 几何检查与直接运行 JavaScript 的回归用例。
- `node --check js/*.js`：验证全部前端脚本的语法。
- 重点断言：`θ=60°` 时的第二次切割使两个候选三角形都包含 `θ` 的正整数倍；演示第 5 步的两个候选三角形都包含 `45°`。
